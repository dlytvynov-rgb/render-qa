# Редизайн «Viewport» + слоти за запитом

**Дата:** 2026-07-15
**Статус:** затверджено Димою (напрям Render Viewport · слоти за запитом · все поетапно)

## Проблема

Поточний вигляд («паперовий» крем + Georgia + blueprint-патерн) — застаріле бачення. Потрібен новий візуальний рівень і зручніше розкладання пакета по типах документів для Cross-Check.

## Візуальна система «Viewport»

Естетика рендер-тула (3ds Max / Corona viewport): темний нейтральний інтерфейс, рендер — головний герой, службова графіка тиха і технічна.

### Токени (`src/theme.css`, CSS-змінні на `:root`)

```css
:root {
  --void:  #131519;  /* базовий фон */
  --panel: #1c1f26;  /* панелі, картки, слоти */
  --line:  #2a2e37;  /* бордери, розділювачі */
  --text:  #e8e6e1;  /* основний текст */
  --dim:   #8b8f98;  /* вторинний текст */
  --amber: #e8a84c;  /* сигнатурний акцент: фокус, прогрес, активне */
  --ok:    #55c47c;  /* статус ok (відкалібрований під темне) */
  --warn:  #e67e22;  /* статус warn */
  --fail:  #ef5350;  /* статус fail (світліший за #e74c3c для темного тла) */
  --info:  #56a8e8;  /* посилання, інформаційні мітки */
}
```

Статусні кольори в JS-константах (`STATUS`, `MAT_STATUS`, `SVERKA_STATUS`, `QA_CHECKS`) на Етапах 1–2 не чіпаємо — вони читаються і на темному; звести їх до токенів можна окремим кроком Етапу 2. PDF-звіти (`generateReport`, `generateTzReport`) **лишаються світлими** — вони для друку.

### Типографіка

- **Archivo** (Google Fonts, ваги 400/500/600/700) — заголовки та UI-текст. Замінює Georgia.
- **IBM Plex Mono** (400/600) — мітки, статуси, чіпи файлів, координати. Замінює системний monospace.
- Підключення: `<link>` у `index.html` + system-fallback стек (`Archivo, "Segoe UI", sans-serif` / `"IBM Plex Mono", Consolas, monospace`) — в offline-Electron падає на системні без поломки.
- Масштаб: 11px базовий UI, 13px акцентний, 16–20px заголовки екранів, 9–10px службові мітки (як зараз, але через класи).

### Сигнатура — «Safe Frame»

Єдиний гучний елемент системи:
- Рендер завжди у темній viewport-рамі: тонкі **куточки-кропи** по чотирьох кутах (2px, `--amber`) + **HUD-мітка** в лівому верхньому куті (`IBM Plex Mono`, наприклад `РАКУРС 1/3 · 12 ВІДМІТОК`).
- **Marching ants** на drag-over будь-якої дропзони: пунктирний бордер з анімацією зсуву (`stroke-dashoffset`/`background-position`, CSS-анімація ~0.5s linear infinite), колір `--amber`. Поважає `prefers-reduced-motion` (анімація вимикається, лишається статичний пунктир).

Решта інтерфейсу — тиха: без тіней-камінців, без градієнтів, 6px радіуси, 1px бордери `--line`.

## Слоти за запитом

- Базові зони лишаються: РЕНДЕРИ / БРИФИ / РЕФЕРЕНСИ / КРЕСЛЕННЯ (+ ТЗ-текст, ARCHIVIZER).
- Кнопка **«+ слот»** поряд з базовими зонами відкриває меню з **усіх типів `DOC_TYPES`** (FFE, RCP, Елевейшн, Ландшафт, Розгортка, Вузли, To-do, План, Референс); вже додані типи в меню не повторюються.
- Доданий слот — картка-дропзона з назвою типу; файли в ній автоматично отримують `_docType` цього типу (селект «тип?» у типованих слотах не показується; у базових зонах лишається).
- Порожній слот прибирається хрестиком; слот з файлами — тільки після видалення файлів.
- Набір доданих слотів зберігається в `localStorage` (`rqa_custom_slots`, масив типів) і відновлюється при старті.
- У промпт файли типованих слотів ідуть за категорією типу: `rcp/elevation/landscape/unfold/detail/floorplan` → до списку КРЕСЛЕННЯ; `ffe/todo` → до БРИФИ; `reference` → до РЕФЕРЕНСИ. Cross-Check-активація працює як зараз (по `_docType`).
- Технічно: один `useFileList("custom")` на кожен доданий слот — керується мапою `customSlots: {type → useFileList}`. Оскільки хуки не можна створювати динамічно, використовуємо **один спільний `useFileList("custom")`** зі слот-фільтрацією по `_docType` (файл при додаванні в слот отримує тип одразу, слот показує `files.filter(f => f._docType === slotType)`).

## Хедер-тулбар

Тонкий DCC-подібний тулбар: логотип-мітка `RENDER QA`, назва екрана, справа — кнопка ⚙ (попап з полями Anthropic key і Archivizer token; постійно видимих інпутів ключів у хедері більше немає), кнопки контексту (PDF, Нова перевірка) як зараз.

## Етапи (кожен — робочий стан)

1. **Токени + екран завантаження**: `src/theme.css`, шрифти в `index.html`, новий хедер з ⚙-попапом, режим-картки, дропзони з marching ants, слоти за запитом, прибрати blueprint-SVG фон.
2. **Grid + DetailPage**: картки ракурсів, Safe Frame навколо рендера (кропи + HUD), вкладки Cross-Check/Звіт/ТЗ у новій системі, статусні константи → токени.
3. **TZ Review**: той самий стиль; PDF без змін.

Етапи 2–3 плануються після того, як Дима подивиться Етап 1 у браузері (дизайн-фідбек важливіший за наперед написаний план).

## Обмеження

- Логіка не змінюється — тільки стилі, розмітка і механіка слотів. Тести `src/sverka.test.js` мають лишатись зеленими без правок.
- Responsive: сітки слотів згортаються в колонку на вузьких вікнах (min-width патерни через `auto-fill/minmax`).
- Доступність: видимий фокус (`outline` `--amber`), `prefers-reduced-motion`.
- Electron/офлайн: шрифти з CDN з системним fallback.

## Верифікація

- `npx vitest run` зелений, `npx vite build` проходить, eslint без нових помилок.
- Ручна: екран завантаження в новій темі, drag-over з marching ants, «+ слот» → RCP-слот → файл у ньому має тип RCP (видно по Cross-Check активації після аналізу), слоти переживають перезавантаження, ключі працюють через ⚙-попап.
